# R04 测试、工作流与文档约束

> 覆盖域：测试（域6）+ 流程与文档（域8）

## 1. 测试门禁（L0/L1）

1. **[L0] 主门禁**：`.venv/Scripts/python.exe -m pytest` 必须 rc=0；覆盖率棘轮 `--cov-fail-under=92`（12 包分母，`pytest.ini` 单一真源）——只升不降，降线须专项裁决
2. **[L0] 不许改断言凑绿**：测试红先归因（夹具错/实现错/环境红三判别），禁止删测试/skip/放宽断言迁就实现
3. **[L1] 单用例快跑**：`pytest tests/test_x.py -o addopts= -q`（清掉覆盖率参数）；快跑结论不冒充门禁结论
4. **[L1] UIA 真窗**：`tests/uia` 默认 `--ignore`（需桌面会话+打包 exe）；发版/触及 UI 装配链时手动跑 `pytest tests/uia -o addopts=`；GUI 装配缝（模式切换→注入→交互→提交→保存）只有 UIA 能覆盖
5. **[L1] 守卫是朋友**：规模/i18n 键集/lite 体积/命名守卫红=按指引修复，禁止绕守卫或 hack 空行
6. **[L1] 并发与长跑纪律**：长命令后台化+轮询（Bash 单次 10min 硬顶）；跑批期间不并行构建；连续红先新鲜复验剥假红再定性

## 2. 提交与分支（L1）

1. **[L1] commit 规范**：`{类型}: W{波次} {一句话}` + 详尽中文正文（关键决策/实测数字/留档结论/门禁计数）——类型 ∈ feat/fix/test/docs/chore/perf；先例见 `git log`（W53 样板）
2. **[L1] 单分支 master + 双远端**：gitee/github 双 remote 双发；提交带 pathspec 防夹带（共享工作区纪律）
3. **[L1] 批次全绿即提交**：工作树不是安全区（08-29 清树事故二次实证）；push 时机留给用户

## 3. 文档与留档（L1/L2）

1. **[L1] PRD/tasks 落 docs/**：重决策（D1-Dn 级"决策+理由"）落 `docs/prd-*.md`——docs 是天然灾备（抗 reset/clean）
2. **[L2] 实验结论留档**：参数扫描/负结果写进 commit 正文或 docs（W52/W53 悬崖扫描范式：不止甜点、扫悬崖、报零产出哨兵指标）
3. **[L2] `.workflow/` 为审计轨迹**：保持 git 跟踪，不忽略

## 4. 自检清单

- [ ] 主门禁 rc=0 且覆盖率 ≥92 不降
- [ ] 新测试覆盖 12 包分母内的改动面
- [ ] commit 带波次号+门禁计数；决策落 docs
