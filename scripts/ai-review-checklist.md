# AI 审查清单与产出契约（七维）

## 审查维度（逐维过，项目化判据）

| 维度 | 项目化审查问题 |
|------|--------------|
| 正确性 | 边界/空输入/None；CUDA 不可用回退路径真的通？返回值语义（哨兵 -1/空串零操作）与调用方一致？ |
| 错误处理 | 吞异常/裸 except？失败有用户可见反馈（诚实回退而非静默 return）？异常路径也释放资源？ |
| 并发时序 | 耗时操作是否又溜回主线程？worker 结果回投后陈旧校验？重入守卫（双发加载竞态）？ |
| 资源生命周期 | 文件句柄释放顺序（close/del 先于 rmtree/unlink）；模型 del+empty_cache+置 None 三步；临时目录异常路径清理；日志 handler 重复添加/多进程混写 |
| 性能 | 热路径分配；重复加载权重/重复预处理；批量推理批大小 vs 显存；O(n²) 图像逐像素循环 |
| 安全 | 路径拼接越界（用户输入拼路径）；密钥/凭据硬编码；权限门（角色不该见的页面）；日志泄敏感数据 |
| 可维护性 | 命名规约（R00）；page.py 800 行守卫会不会被击穿；i18n 键增删同步；单一真源；孤儿代码（删功能漏删配套） |

## 产出契约（硬性，防注水）

1. 按维度输出 findings，每条必须含：`严重度 P0-P3 + 文件:行 + 一句证据 + 修复建议`。
2. 只报 diff 中有证据的问题——不臆测未展示的代码，读不到的写"未覆盖"。
3. 某维度无发现就写"该维度无发现"，禁止凑数、禁止风格挑刺（最多 3 条 Nit）。
4. Blocker/Should 均为 0 时，必须明确写"本次未发现缺陷级问题"，再用 Nit 补全。
5. 结尾给一行结论：`建议：可合入 / 修复 P0 后可合入 / 阻塞`。
