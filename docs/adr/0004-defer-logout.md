# ADR 0004：显式登出（logout）暂缓实现

- 状态：已接受（W57 · v7 P3-4 决策收口）
- 日期：2026-09-16
- 背景：v6 P3-4 / v7 承接——应用无登出入口，`session.reset_current_user/reset_current_role` 生产零消费（docstring「登出用」承诺未兑现），admin 离席后会话持续至进程退出。

## 决策

**暂缓实现登出**，`reset_*` 保留为测试接缝并在 docstring 修正承诺语义（不宣称「登出用」）。重启应用即重置会话（现状等价于"重启即登出"）。

## 理由

1. **威胁模型内无增量风险**：单用户工作站场景，能操作键盘者本就可重启进程绕过任何登出；`configs/users.json` 可读者本就是机器主人（v6 P3-11 同口径）。
2. **权限护栏已闭环到当前边界**：W39 反转后未登录/未知角色归一 operator 最小集，登出后的可见面与未登录一致——登出按钮在当前矩阵下不改变任何安全边界。
3. **产品决策面未成熟**：登出涉及会话超时策略、锁屏 vs 回登录页、未保存标注处置（换图清空后 W55 语义）等多个交互决策，宜在真实用户反馈后一并定形，避免反复改 UIA 契约。

## 重开触发条件（满足任一即复审）

- 多用户共享同一工位（交接班场景）成为真实需求；
- 引入会话超时 / 屏幕锁定需求；
- 权限矩阵收紧（动作不再三角色全放行）使「登出降权」产生真实边界差异。

## 后果

- v7 P3-4 状态从「未闭环」转为「显式决策暂缓」（ADR 豁免）；
- 实现时最小路径已备好：`reset_current_user/reset_current_role` + 回登录页导航（shell 现有 LOGIN_PAGE 常量），预计 0.2 人日 + UIA 一条用例。
