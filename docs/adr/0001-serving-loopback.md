# ADR-0001：serving gRPC 服务锁定回环地址（127.0.0.1）

- **状态**：已接受（2026-08-17）
- **关联**：v2 架构审查 P2-6（决策债务）/ P2-18（gRPC 无鉴权无 TLS）；v1 文档跟进表第 12 项
- **范围**：`serving/`（gRPC + 共享内存对外服务）及其文档示例

## 背景

AutoVisionAgent 的 serving 层通过 gRPC（`serving/server.py` 的
`add_insecure_port`）+ Windows 共享内存文件对外暴露推理能力，供本机
.NET 客户端（VisionAgent.Shared）调用。服务现状：

1. **无 TLS**：端口以 insecure 方式监听，流量明文；
2. **无 token/鉴权**：任何能连到监听端口的进程都可调用
   LoadModel / Detect / ReleaseSharedMemory；
3. **共享内存文件落 %TEMP%**：本机任意进程可读推理载荷。

v1 架构文档跟进表第 12 项要求就此做出正式决策（127.0.0.1 锁定 vs
TLS+token），悬置未产出（v2 P2-6）；同时 v2 P2-18 指出模块 docstring
用法示例示范了 `--host 0.0.0.0` 暴露路径，与"默认回环"的实际缓解相互
矛盾（该示例已随本 ADR 一并修正为 127.0.0.1；W13 的 P1-2 config 收敛
亦已删除死配置 `ServerConfig host="0.0.0.0"`）。

## 决策

1. **默认且推荐的拓扑 = 回环锁定**：`--host` 默认 `127.0.0.1`
   （CLI、`AVA_HOST` 环境变量、`create_server`/`serve` 形参均默认回环）。
   文档与示例一律使用 127.0.0.1，不示范 0.0.0.0。
2. **不引入 TLS/token**：本产品是单工位、单用户、服务端与 .NET 客户端
   同机的学习项目。回环绑定已把暴露面从"网络可达"收缩为"本机进程"，
   而 TLS 证书管理与 token 分发的复杂度超出该威胁模型的收益。
3. **跨机部署属显式越界**：如确需跨机，使用者须自行传 `--host 0.0.0.0`
   并自担风险——该路径不承诺安全（无鉴权、无加密）；若未来真出现跨机
   需求，应另立 ADR 引入 mTLS/token，而非默认放开。

## 后果

- 正向：默认拓扑与威胁模型一致；同机客户端无连接性损失；决策留档，
  P2-6 悬置收口。
- 已接受的残留风险：本机恶意进程仍可连 `127.0.0.1:50051` 或读
  %TEMP% 共享内存文件（与 localhost 信任同级，属本地威胁模型内）。
- 后续加固项（非本 ADR 强制）：`--host` 传入非回环地址时在启动日志
  打 WARNING 提示越界；共享内存目录 ACL 收紧。

## 备选方案（已拒绝）

- **TLS + token**：见决策 2，复杂度/收益不匹配。
- **Unix domain socket / named pipe**：.NET gRPC 跨语言集成成本高，
  且 Windows named pipe 默认同样无鉴权，收益不抵改动。
