# AutoVisionAgent 产品规划（2026 Q4）

- 版本：v1.0 草案（2026-09-29，基于 HEAD 能力盘点）
- 作者：产品规划会话（PM 技能产出）
- 定位声明：**离线优先的工业视觉检测一体化工作站**——把"标注 → 训练 → 推理 → 评估 → 部署"压缩到一台 Windows 工位机上，让中小制造企业的质检线不依赖云和算法工程师。

## 1. 现状盘点（基于当前 HEAD，2026-09-29）

### 1.1 能力矩阵与"真实度"标注

产品最大的隐性风险是**能力真实度不均**：UI 上存在的功能，底层可能是真实现、半实现或模拟回退。规划第一原则：先把矩阵说诚实。

| 页面/能力 | 状态 | 真实度证据 |
|---|---|---|
| 登录/权限（admin/engineer/operator 三角色） | ✅ 完整 | 审计日志+页面门控+UIA 验证；凭据已持久化（W68） |
| 标注（手绘多边形/矩形/关键点 + SAM3 辅助） | ✅ 完整 | SAM3 真权重异步标注（ADR-0003）、同名 LabelMe JSON 识别（W59b）、撤销重做（W1/W55） |
| 数据管理（导入/统计/划分/导出 YOLO/COCO） | ✅ 完整 | 同目录 LabelMe 计数（W59）、自然排序（W20）、向导自动导出（W65） |
| 训练 | ⚠️ **部分真实** | seg/det 真训练已验证（W58/W69，含任务自动选择）；**其余 7 类任务引擎（cls/pose/ocr/pseg/abdet/sgan/super）仍为模拟回退**；进度为一次性适配（无逐轮曲线） |
| 推理（单张/批量/CSV 导出） | ✅ 完整 | 自产权重批量 8/8 验证（W58） |
| 评估 | ✅ 基础完整 | mAP 等指标；无阈值优化建议 |
| 发布（ONNX/TensorRT 导出） | ⚠️ 框架在 | UI+exporter 后端在，**导出产物在真实 TRT 环境的验证未闭环** |
| 缺陷生成 | ⚠️ 引擎在 | sgan_blend 等引擎注册，产品化程度低 |
| 项目管理（版本快照/对比） | ✅ 基础完整 | versioning 快照+diff（W19） |
| gRPC serving（serving/） | ⚠️ 底座在 | 回环绑定+共享内存传输已实现，**无 UI 入口，未纳入测试面** |

### 1.2 质量基线（规划的"不可回退线"）

- 主门禁：**1279 单元/集成测试全绿**，覆盖率 ≥92%，ruff 0，i18n 双向守卫，行数守卫
- UIA 端到端：**24/24 全绿**（含极柱真实数据全链、向导链真训练、SAM3 深测、改密、权限门控）
- 已知债务：幽灵训练异常（未复现，挂账）、AMP 预检同步阻塞（反馈已前置，异步化待做）、lite 派生包、登出暂缓（ADR-0004）

### 1.3 已实证的目标场景

极柱外观检测（用户真实案例）：1288 张 bmp、6 类缺陷（YS/ZW/Z/TJYS/Circle/HS）、多边形标注 → YOLO-seg 真训练 → 批量推理 → CSV 导出。**从"标注完的文件夹"到"真训练产出模型"已是一条按钮级路径**（W62-W69 向导链）。

## 2. 目标用户与核心场景

- **Persona 1｜质检工程师（主用户）**：工厂现场，非算法背景。打开软件 → 打开已标注文件夹 → 一路"下一步" → 得到能跑的检测模型。痛点：不会写训练脚本、产线电脑不能联网。
- **Persona 2**：**设备/IT 工程师（部署者）**：把模型导出到检测主机（可能无 Python 环境）。痛点：ONNX/TRT 环境差异、模型版本混乱。
- **Persona 3**：**质量主管（买单者）**：要报告、要可追溯。痛点：检测了什么、漏了什么说不清。

北极星指标：**首案例时间（安装软件 → 产出产线可用模型）**。当前实测约半天（含标注）；目标：对"已有标注数据"的用户压到 **2 小时内**（自动导出+自动选任务已达成，剩余瓶颈在训练进度不透明与部署验证）。

## 3. 差距分析（按用户旅程排序）

| 旅程环节 | 现状 | 差距 | 影响 |
|---|---|---|---|
| 训练 | seg/det 真实，2 轮起训 | ① 进度一次性（100 轮看不到逐轮曲线/剩余时间）② 其余任务类型点开始=假训练（UI 标了"模拟"但用户不理解）| 信任感；长训练不敢跑 |
| 模型管理 | outputs 下散落 .pt | 无训练历史列表/对比/一键加载推理 | 调参迭代靠翻文件夹 |
| 部署 | ONNX/TRT 导出 UI 在 | 导出产物无"在目标机跑通"验证故事；无模型卡（输入尺寸/类别表）| Persona 2 不敢用 |
| 数据 | 导入/划分/统计 | 无增强（工业常用的旋转/亮度/划痕叠加）；缺陷生成未产品化 | 小样本缺陷场景效果差 |
| 评估 | mAP 表格 | 无 PR 曲线/混淆矩阵/阈值调优选荐 | 不知道阈值该设多少 |
| 报告 | CSV | 无检测报告（批次级 PDF：通过率/缺陷分布/图证）| Persona 3 无交付物 |
| 协同 | 单机 | 项目包导入导出（已有雏形）未成体系 | 多工位/离线交付靠拷目录 |

## 4. 规划原则

1. **真实度优先于广度**：UI 暴露的能力必须真实或明确拦截，模拟仅限显式选择（延续 W69 判例）
2. **离线优先**：一切功能在无外网工位可用（延续 W64/W70 资产随包判例）
3. **向导优先**：主路径按钮级可达，高级参数收进折叠（延续 W59c-W65 向导链）
4. **每波交付可验收切片**：沿用结构化开发工作流（L1/L2/L3 定档+门禁），波末 DoD 先验

## 5. 路线图（三波，RICE 排序）

### 第一波｜可信训练与模型资产（约 2-3 周，速赢+战略）

| # | 事项 | 价值 | 量级 | 验收（DoD） |
|---|---|---|---|---|
| 1.1 | **训练逐轮进度与曲线**：一次性适配器改造为逐轮回调（loss/epoch/剩余时间），训练页实时曲线 | 高（信任感×长训练可用性） | M | UIA：训练中可见 ≥N 个进度点；中断可恢复 UI 状态 |
| 1.2 | **训练历史与模型资产页**：列出历史训练（任务/骨干/数据集/mAP/时间），一键"加载到推理"；模型卡（类别表/输入尺寸） | 高（Persona 1 调参闭环） | M | UIA：训练完成→历史出现→一键加载→推理可用 |
| 1.3 | **模拟训练彻底显式化**：非真训练任务在下拉中灰显+说明，点开始弹确认（消灭"假曲线"误会） | 中高（W69 用户报障的直接收口） | S | UIA：选模拟任务→有显式确认；单元：门禁测试 |
| 1.4 | AMP 预检异步化 + 幽灵训练观察收口 | 中 | S | 预检在 worker；挂账项复现即修 |
| 1.5 | 首启体验：允许安装时配置初始密码（工位交付不再txt明文） | 中 | S | 设置页改密后 txt 删除提示已有；补安装参数 |

### 第二波｜部署闭环与数据增强（约 1-1.5 月）

| # | 事项 | 价值 | 量级 | 验收 |
|---|---|---|---|---|
| 2.1 | **部署验证闭环**：ONNX 导出后内置一致性校验（同图 pt vs onnx 输出差异报告）+ 模型卡随包导出 | 高（Persona 2 敢用） | M | UIA：导出→校验报告生成 |
| 2.2 | **评估增强**：PR 曲线、混淆矩阵、按类阈值调优选荐（"建议 conf=0.37，通过率/漏检平衡点"） | 高（Persona 1 每次都用） | M | 单元：阈值建议算法；UIA：评估页渲染 |
| 2.3 | **数据增强管线**（旋转/翻转/亮度/噪声/马赛克，训练时即时增强，预览开关） | 高（小样本缺陷场景） | M-L | 训练增强开关→样本数×K 生效；UIA 预览 |
| 2.4 | 任务引擎真训练扩展：cls（分类）优先（工业第二常见），pose/ocr 视需求 | 中 | M/个 | cls 真训练 e2e 冒烟（同 W69 模板） |
| 2.5 | 缺陷生成产品化一期：缺陷模板+背景合成入库（sgan 底座） | 中 | M | 生成图可直接进训练集 |

### 第三波｜体系化与规模化（季度级）

| # | 事项 | 价值 | 验收 |
|---|---|---|---|
| 3.1 | **检测报告**：批次级 PDF（通过率/缺陷分布/可疑图证/模型版本/审计链） | 高（Persona 3 买单） | UIA：批量推理→报告生成 |
| 3.2 | **项目包 2.0**：数据+标注+模型+评估快照一键导出/导入（血统完整） | 高（多工位/离线交付） | 双机往返一致性校验 |
| 3.3 | gRPC serving 产品化：设置页启停+密钥+健康检查（底座已在） | 中（接入 PLC/上位机） | 集成测试+文档 |
| 3.4 | 多相机采集集成（GigE/USB 相机采集页） | 高（进入实时检测） | 需硬件验证——外部闸门 |
| 3.5 | 无监督异常检测产品化（abdet/sgan 引擎底子） | 中（免标注场景） | 立项前先做用户验证 |

**明确不做（本季度）**：云端训练中心、多租户 SaaS、自然语言交互——与"离线工位"定位冲突或无需求证据。

## 6. 风险与依赖登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| UIA 套件对桌面会话依赖（锁屏/远程会话竞态） | 中 | 已有 Invoke 化通道+语言钉；跑批纪律固化为发版门禁 |
| ultralytics 版本升级破坏一次性训练适配器 | 中 | 适配器已隔离；升级前跑 e2e 冒烟 |
| 多相机硬件验证不可本地化 | 高（3.4） | 立项前要求用户提供远程工位或样机 |
| 单人维护带宽（当前一人+AI 协作节奏） | 高 | 严格按波次切片，每波可独立发版 |

## 7. 待用户裁决的决策点

- **D-1**：第二波 2.4（cls 真训练）是否提前——取决于您手上是否有分类检测的真实需求（极柱是分割）。
- **D-2**：3.4（相机采集）的硬件条件何时具备——它决定第三波是"报告/体系化"还是"实时检测"先行。

## 8. 与工程节奏的衔接

本规划与仓库现有 SDW 流程对齐：每项事项按 L1/L2/L3 定档走门禁；若跨周执行，建议在 `docs/roadmap-autovisionagent.md` 落 Program 层文档（波次 DoD+快照），本文件作为产品侧输入源。
