# AutoVisionAgent 质量属性场景（架构审查 2026-08-24）

> 关联：`architecture-review.md` · 场景格式：刺激 → 响应 → 度量 → 现有证据/缺口。
> 用途：为补救计划提供可验收的质量属性锚点；避免"泛泛质量检查表"（对齐 skill 门禁）。

## QS-1 交付可重复性 · 错误环境打包防呆（关联 AVA-R1）

- **刺激**：维护者（或 AI 会话）用非 `.venv` 解释器执行 `python -m PyInstaller autovisionagent.spec --noconfirm`。
- **期望响应**：构建立即失败，输出指明唯一合法入口（R01 §2）。
- **度量**：失败发生在 Analysis 阶段前（<5s），退出码非 0，错误信息含 ".venv" 字样。
- **现状**：无防呆——本会话已实际产出 3.5MB 残废 exe（证据：会话记录 + 任务 W-2 修复轨迹）。缺口确认。

## QS-2 门禁可信度 · 外部验证存在性（关联 AVA-R2）

- **刺激**：任意提交推送到任一远端。
- **期望响应**：ci.yml 双 job（pytest offscreen / dotnet test）自动运行并回传状态。
- **度量**：feature 分支存在远端 CI 运行记录；红/绿可追溯。
- **现状**：ci.yml 就绪但 feature 分支未推送、领先 gitee/master 8 提交——外部验证记录为零。缺口确认。

## QS-3 可靠性 · 有界停机（关联优势基线，防回归）

- **刺激**：用户在批量推理 + SAM3 预热进行中点击窗口关闭按钮 ✕。
- **期望响应**：确认对话框 → 确认后 `jobs.request_stop_all` 协作取消，全部后台线程在预算内退出；超时任务名落入 warning 日志。
- **度量**：关停总时长 ≤ `_EXIT_*` 常量预算；无僵尸进程残留（任务管理器核对）。
- **现状**：机制已落地（shell.py:328-370，W15-J4），UIA 真窗套件有覆盖；属守住的基线，回归由发版检查单兜底（见 QS-5 缺口）。

## QS-4 可维护性 · 依赖方向不变式（关联优势基线）

- **刺激**：新开发者提交在 `core/` 内 import `gui` 或 `labeling` 的代码。
- **期望响应**：被规则或门禁拦截（grep 语义检查 / check-gate 段落）。
- **度量**：`grep -E "^(from|import) (gui|labeling)" core/` 恒为 0。
- **现状**：实测 0 违规（本次审查 grep 证实）；但拦截靠规则文档（R01）而非 check-gate 内建检查——建议纳入 P3 观察（低成本高确定性）。

## QS-5 GUI 交互回归 · 真窗发现时延（关联 AVA-R4）

- **刺激**：引入"GUI 可启动但关键交互缺失/损坏"的缺陷（如本次审查前的"exe 无关闭按钮"）。
- **期望响应**：在合入前或至迟例行周期内被 UIA 真窗套件捕获。
- **度量**：交互缺陷从引入到发现的时延；当前实际值 = 到发版检查单（手动，周期=发版间隔）。
- **现状**：pytest.ini `--ignore=tests/uia` + CI 不跑 → 发现时延无上界保证。缺口确认。

## QS-6 交付物体积 · 分发预算（关联 AVA-R5/R3）

- **刺激**：torch/依赖升级或新增可选引擎（如 SAM3 transformers 栈）。
- **期望响应**：完整 dist 与 lite 双产物体积均受棘轮约束，超线即门禁红。
- **度量**：完整 dist <7GiB（拟设）；lite <2GiB（既有 L0 棘轮）。
- **现状**：lite 有棘轮但当前产物缺失（skip 盲区）；完整 dist 无棘轮且已 4.3→6.36GiB（+48%）。缺口确认。
